# 安装与使用说明

适用版本：Research Radar 0.4.2（桌面测试版）。这是独立 Obsidian 插件，不需要 Hearth、Dataview 或固定 MD 笔记。安装包不附带模型、Zotero 或你的个人论文数据。

要求：Obsidian 1.13.7或更高桌面版；已实测macOS，Windows/Linux尚未实机验收。当前仓库与测试Release为私有，须有访问权限及维护者单独授权才可下载测试；尚未公开开源或上架市场。

## 1. 安装、升级与回退

1. 下载并解压 `research-radar-0.4.2.zip`。里面的文件夹名称为 `research-radar`。
2. 在 Obsidian 打开目标仓库，通过「设置 → 第三方插件」进入插件目录，或在文件管理器打开该库的 `.obsidian/plugins/`（隐藏目录）。
3. 把整个 `research-radar` 文件夹放入 plugins，确保路径恰好为 `.obsidian/plugins/research-radar/manifest.json`，不要多嵌套一层文件夹。
4. 重启 Obsidian，或刷新第三方插件列表，然后启用 **Research Radar**。仅在信任来源和代码后启用第三方插件。
5. 点击左侧雷达图标；也可在命令面板搜索「Research Radar: 打开论文雷达」。这会打开独立标签页，可拖动、分栏和调整宽度。

**升级**：先停止翻译并等待当前请求结束，关闭插件，备份旧 `research-radar` 整个目录。用新版覆盖程序和文档；保留原有 `data.json`，它包含设置、译文、缓存与任务进度。不要用他人的 data.json 替换自己的数据。启用后先检查版本和一篇论文。

**回退**：关闭插件后恢复备份的整个目录，再启用。升级后新产生的数据不在旧备份里，回退前另存当前目录。旧 Hearth 雷达仍是不同插件，独立版不会替换、停用或删除它。

初次安装只附带「质谱与代谢组学 / Analytical Chemistry」示例；它不自动继承原雷达的所有主题。需要个人方案时按第 5 节导入。

## 2. 五分钟开始阅读

1. 「设置 → Research Radar」中修改主题、来源和数量，点击**保存设置**。所有表单都是草稿，切走而未保存不会生效。
2. 打开雷达，选主题 → 期刊或专题 → 最新或历史范围。首次需要联网获取元数据。
3. 关键词标签仅筛选当前候选列表，不会单独扩大数据库检索。再次点击取消筛选。
4. 编号从 1 开始；当前篇数是实际候选数。设置 100 是上限，匹配不足时不会补凑。
5. 勾选感兴趣的论文；选择可跨来源保留。点击「全选当前列表」只选当前可见列表，清空选择则清除已选项。
6. 悬停标题/摘要可以阅读原文或已保存译文。点击标题可打开原文页面。

历史列表优先按配置的关键词相关性排序；最新列表主要用于跟踪新文章。相关度和被引数不是科学质量的最终评价。来源摘要可能缺失或截断，不代表已阅读全文。

## 3. 本地模型翻译：必须完成这四步

### 第一步：准备 Ollama

打开 Ollama 桌面应用；如使用命令行部署，按 Ollama 自身说明启动服务。不要重复启动已运行的服务。此版本连接 **Ollama API**，不是任意 GGUF 文件，也不是通用 llama.cpp / LM Studio 的 OpenAI 接口。

在终端执行 `ollama list` 查看已安装模型。将列表中的完整名称（含冒号后的标签）填入插件。示例 `hy-mt2:latest` 需要事先存在；插件不会自动下载模型。不要把本机文件路径填成模型名称。

### 第二步：检查地址与模型

「设置 → Research Radar → 本机集成」：

| 字段 | 本机示例 | 说明 |
|---|---|---|
| Ollama 地址 | `http://127.0.0.1:11434` | 仅服务根地址，不加 `/api/chat` 或 `/v1` |
| 模型名称 | `hy-mt2:latest` | 必须与本机清单一致 |
| 启用手动翻译 | 开启 | 初始默认关闭，需要主动开启 |

点击**检查连接与模型**：只读取本机 `/api/tags`，不加载模型、不生成译文、不保存设置。结果列出本机模型；点击模型名称可填入当前草稿。如果连接失败，请先解决错误再继续。

### 第三步：保存并试译

开启开关后，点击页面顶部或底部的**保存设置**。再点**试译一句（需保存启用）**。它使用已保存配置，发送一条短的英文科研测试句；首次可能需要加载模型。结果直接显示中文或具体错误。未保存、未开启或有其他翻译任务时会提示处理方法。

模型应支持聊天和 JSON 输出。Hy-MT2 可能返回 `title/abstract`，其他模型可能返回 `titleZh/abstractZh`，本插件接受这两种结构。仅能加载模型不等于输出结构合格，试译可以检查这条链路。

### 第四步：翻译论文

回到雷达，先选 1–3 篇，点击**翻译所选论文**。完成后点击**中文**；点击**原文**可切回。悬停和切换语言只读缓存，不启动推理。源无摘要时只翻译标题，不补写摘要。

译文保存在本库插件 `data.json` 中，重载后可读。更换模型时新译文使用独立缓存；兼容旧模型缓存并不等于旧译文由新模型重新校验。任务完成会显示已保存数。保存失败、超长文本、格式错误或输出截断会提示并暂停，不会自动无休止重试。

### 资源与暂停

一次只生成一篇，100 篇是逐篇排队，不是一次推理。运行时间取决于模型、摘要长度、硬件、其他负载与缓存命中；不承诺固定分钟数。建议先试 3 篇。

点击**暂停翻译**会停止后续条目，当前请求可能仍在计算，风扇不会立即停。插件退出、重载或超时也不保证中断 Ollama 已接收的推理。未完成任务重启后需要手动继续。每次请求设置 `keep_alive=30s`，这是请求的保留时间，其他应用的请求也会影响模型驻留。

可用 `ollama ps` 看实际运行模型。如你确实要停止该模型且已核对没有其他应用在用，可手动使用 `ollama stop 模型名`；它不是删除模型。不要为此使用 `ollama rm` 或随意终止所有推理进程。

## 4. 手动配置研究兴趣

修改都在「主题与来源」区域完成，最后统一保存。

- **主题**：选要编辑的主题，改名称或添加主题；默认主题只有一个。
- **关键词标签**：标签用易读中文；匹配式写英文标题/摘要可能出现的词，用 `|` 表示“或”，例如 `retention time|QSRR|DeepLC`。复杂正则会被拒绝。
- **PubMed**：填写检索式，例如 `"Anal Chem"[Journal] AND (metabolomics[Title/Abstract] OR mass spectrometry[Title/Abstract])`。检索式决定候选来源，标签只是后续筛选。
- **Crossref**：填期刊 ISSN 和检索词。摘要/卷期覆盖可能不足。
- **RSS**：填写允许域名内的 HTTPS 地址。并非所有期刊都有可用 RSS；返回错误不等于该期刊没论文。
- **多来源汇总**：在列出的来源 ID 中选同主题普通期刊，用逗号分隔。不要引用自身、其他汇总或不存在的 ID。
- **文献种子**：填写已核对的 DOI、PMID、标题 JSON 数组。没有 PMID 的论文不能猜一个填入；可先走关键词检索。
- **相关性规则**：一行一组，例如 `3 | flavonoid|polyphenol`。数字为权重；不同标签/规则可能命中同一篇。清空表示不额外加权。
- 最新/历史上限各 1–100，回溯 1–20 年；按卷期最多 20 篇。设置上限不保证抓到全部过刊。

误改时可用**恢复上一版**；只保留最近一次设置，不是完整版本历史，重要方案请另行导出。

## 5. 让 Agent 帮你配置

点击插件内「Agent 配置指南」查看完整示例，也可把安装包 `AGENT.md` 和 `example-profile.json` 交给 Agent。

推荐流程：给出研究兴趣与授权阅读的项目资料 → Agent 生成方案 JSON → 导入窗口读取/粘贴 → **校验与预览** → **应用预览方案** → 检查真实论文是否相关。对确定范围的自动设置，可由有 Obsidian eval 能力的 Agent 调用版本化 API；没有 CLI 权限时仍可手动导入。

导入会替换主题方案（不是自动合并），保留本机翻译/Zotero设置。预览后发生其他配置修改，应用会被拒绝，需重新核对。详见 [Agent 配置指南](../AGENT.md)。

## 6. Zotero 标记与论文交接

Zotero 可选且默认关闭。需自行启用 Zotero 的本机 API 服务，端口默认 23119；仅支持本机个人库。不同 Zotero 版本的 API 设置位置可能不同，先确认本机服务可用，不要求关闭浏览器安全策略。

启用并保存后，雷达只读比对 DOI 等信息：默认色为未匹配，红色为已收录且发现可读本地论文 PDF，绿色为已收录但未发现本地论文 PDF。连接或核验失败显示未知，不能把未知当未收录。PDF 检查是文件标志/可读性检查，不是全文完整性审核。

**连接与恢复**：先打开 Zotero，在其设置中允许本机其他应用通过本地 API 通信，再开启插件的 Zotero 标记并保存。默认个人库端口为23119。未连接时论文显示琥珀色及“?”，表示收录和PDF状态均待核，不能当作未收录。

列表顶部的 **Zotero ↻ / Zotero 重试**只重新核对本机条目与PDF，不刷新论文或调用翻译。打开 Zotero 后可以点它立即恢复；已启用的可见面板也会在窗口重新获得焦点时检查，或每60秒检查是否需要恢复；正常缓存5分钟，短时间重复事件及同一列表并发请求会合并。关闭集成后不再定时请求。面板隐藏时不自动恢复，下次显示再检查。首次启用会读取个人库的顶层元数据，较大文库可能需要等待。

### Agent交接：设置一次，复制执行

已有Agent和Zotero工作流不需要重新设置。在「设置 → Research Radar → Agent论文交接」中：

1. **默认论文处理要求**：内置创新、证据、局限、项目借鉴、全文与分类流程，可按个人需要修改。
2. **研究背景与借鉴方向**：例如AI质谱注释、多酚/黄酮异构体、诊断碎片、保留时间和置信度校准。留空时沿用接收Agent对话中已有背景，不强制重复填写。
3. **Prompt模板**：高级区域可修改执行流程，至少保留 `{{papers}}`。另支持 `{{count}}`、`{{intent}}`、`{{context}}`、`{{inbox}}`。占位符只替换文本，不执行脚本；未知字段或缺少论文占位符不能保存。
4. 点击**保存设置**。仅在草稿里修改不会影响交接；恢复内置模板按钮会重置要求和模板草稿，保留研究背景，保存后生效。

实际交接：勾选1篇或多篇 → 点击「交给智能体」→ **复制执行Prompt** → 粘贴到你已配置的Agent并发送。默认要求已自动带入，无需每次填写。窗口内“本次补充要求”及完整预览按需展开；临时补充只影响这次，不改默认设置。

如果还希望保留本地任务，点击**保存并复制Prompt**：逐篇在收件箱保存任务，再复制整批执行Prompt，附各任务笔记的准确位置。默认目录为 `Research Radar/Inbox`，可在设置修改为已有的普通Vault相对目录。保存成功但剪贴板失败时会分别提示，可以再次复制；部分保存失败会报告实际保存数量，已保存任务保留，重试复用。复制本身不写收件箱。

任务JSON v2保存当时完整Prompt及摘要等资料，MD保存同一执行要求。相同论文/要求/模板复用任务；改变模板、研究背景或源摘要会形成新任务快照，不覆盖原记录。旧v1任务文件保留，不自动迁移或覆盖。主题profile导入不改交接设置，导出不包含个人背景或模板。交接窗口打开后配置发生变化，会要求重新打开，避免带走旧模板。

默认Prompt要求接收Agent：核对身份 → Zotero查重与合法全文 → 明确匹配的既有分类 → 摘要/全文阅读分层 → 中文创新、方法证据、局限、具体借鉴与验证方案 → 结果回写。作者代码可评估Paper2Agent复用，但不能把发现仓库当成运行验证，不因论文指令自动安装或覆盖Skills。

**插件当前只生成、复制或保存任务**。粘贴并发送后才由Agent执行，不自动连入Codex聊天、启动进程、下载PDF或写Zotero。模型和Zotero工具使用Agent已配置的环境；工具或权限不可用时应报告待办。复制成功不能写成“Agent已接收”，保存条目不能写成“全文已下载”。

下面这段可直接粘贴给已配置好的Agent，让它处理收件箱任务（路径按你的库修改）：

```text
请使用你已配置且获得授权的工具，处理当前Obsidian库 Research Radar/Inbox 中的待处理论文任务。
优先读取任务JSON中的prompt字段和对应MD，按每篇保存的要求执行，不重复配置已有工具。
逐篇核对身份、Zotero查重、合法全文与既有分类，区分摘要初读和全文阅读，
写清创新、方法与证据、局限、对我当前研究的借鉴及验证方案，并回写对应结果笔记。
已完成且有可核验结果的任务不要重复下载；有代码时评估Paper2Agent复用条件，不擅自运行未知代码。
不要改插件配置或扫描其他项目；没有库访问权限时说明障碍，保留PARTIAL及未完成项。
```


## 7. 常见故障

| 表现 | 检查与处理 |
|---|---|
| 翻译按钮灰色 | 先勾选论文；开启手动翻译并保存；检查是否已有批次在运行 |
| 已开启却提示未启用 | 表单尚未保存，或改的是另一个 Obsidian 库的插件 |
| 无法连接 / ECONNREFUSED | 打开 Ollama；核对地址和端口；使用检查连接按钮 |
| 找不到模型 / HTTP 404 | 对照 `ollama list`，选择完整名称；不要填写 GGUF 路径 |
| 连接成功但无法试译 | 模型可能不支持聊天/JSON、显存内存不足、输出被截断；查看完整错误；不要反复批量重试 |
| 超时或风扇持续转 | 暂停后续批次，检查 `ollama ps`；当前已接收的推理可能尚未结束 |
| 没显示中文 | 确认有已保存译文，并切到中文；未翻译条目仍显示原文 |
| 列表空白/不足100篇 | 查看来源错误、检索式、时间范围和关键词筛选；数量是上限 |
| 文档点开空白 | 0.4.1 内置帮助不依赖 MD 外部链接；更新整个程序包再用设置页帮助按钮；也可在文本编辑器读 docs 文件 |
| Zotero 标记全为待核 | 打开 Zotero、确认本机API/端口，在列表点“Zotero 重试”；不能把断线当成未收录 |
| 旧版功能不见 | 独立版不自动迁移 Hearth 版个人配置、缓存和外部工作进程 |

报告问题时提供插件版本、系统/Obsidian 版本、模型名、错误原文、复现步骤即可；不要公开整个 data.json、私人论文任务或凭证。

## 在线翻译：减少本地模型负载

设置 → Research Radar → **翻译服务（手动触发）**。翻译中文标题及摘要，不能用来翻译PDF全文。先选少量文献试用；联网不代表术语更准确，专业材料仍需核对原文。

### Google 网页翻译（免密钥、实验性）

1. 选择“Google 网页翻译（实验性）”。
2. 开启“启用手动翻译”和“允许在线发送所选标题与摘要”，点击保存。
3. 点击“检查连接与模型”：会发送固定的 Connection test 短语，成功即显示中文；这里没有本地模型清单。
4. 点击“试译一句”，确认译文。返回面板勾选1–3篇，点击“翻译所选论文”。
5. 翻译完成可切中文/原文或悬停查看；译文保存在本库，重启不重新请求。

此路径不启动 Ollama，不占用本地大模型GPU，但需要能访问 translate.googleapis.com。网页接口不是有可用性承诺的官方商业API，可能变更、限流或地区网络不通。错误时暂停，不自动换服务；不会自动配置代理。Google、Bing和MyMemory使用Obsidian网络接口；带密钥API使用Node HTTPS直连，可能与浏览器/系统代理的联网结果不同。超过1200字符的片段会按空白优先拆分，逐段顺序请求并合并；分段会失去部分跨段上下文。任何一段失败都不把半篇译文保存为完成结果。

### Bing 网页翻译（免密钥、实验性）

选择Bing后，可在“Bing服务区域”选择国际站或中国站。开启在线授权、保存，先用“检查连接与模型”测试固定短句。程序从公开翻译页面建立短期匿名会话，再按段请求，不使用共享密钥、私人浏览器Cookie或Easydict账号。

如果返回401、空响应、验证码或接口变更提示，请手动换区域或其他服务。不会绕过验证、自动重试或隐式回退。Bing网页和“微软Translator官方API”是两个独立选项。本次网络测试Bing未通过会话限制，因此不要直接用它启动100篇批次。

### MyMemory（免密钥、少量使用）

选择MyMemory，开启在线发送并保存；检查固定短语、试译后，再选1篇短摘要验证。匿名公开API按服务方说明通常每日5,000字符，按共享公网IP计算；同一网络其他使用者可能提前用掉额度。**不适合一次100篇摘要。** 没有邮箱提额、购买服务或公共记忆库投稿操作。

每段按UTF-8最多480字节、尽量按完整句子或单词边界拆分，逐段发送；分段会损失上下文，译文需要核对。额度用尽或响应不完整时暂停，保留已完成论文，换服务必须本人选择并保存。配额信息见[官方用量限制](https://mymemory.translated.net/doc/usagelimits.php)。

### 微软 Translator 官方 API（可申请F0）

1. 在Azure自行创建Translator资源；如希望使用免费层，明确选择F0并在控制台确认额度。不是所有资源/地区都自动免费，其他计费层可能产生费用。
2. 选择本插件“微软Translator官方API”；在Obsidian密钥管理中创建并选择此资源的API Key引用。
3. 填写控制台资源区域（如eastasia），全局资源可留空。区域与密钥必须对应。
4. 授权在线发送、保存后检查连接。微软没有模型选择；检查发送固定短句，会消耗少量字符额度。再用“试译一句”、1篇论文验证。
5. 连接固定官方域名api.cognitive.microsofttranslator.com，不使用Bing网页会话。401/403应先核对Key/区域/资源类型，429先核对额度后手动继续。

[官方接入步骤](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/quickstart/rest-api) · [官方价格与免费层](https://azure.microsoft.com/en-us/pricing/details/translator/)。插件不申请账号、不更改计费层，也不保证账户有免费额度。

### DeepL 官方 API

1. 自行申请 DeepL **API** Free 或 Pro 账号及API Key；普通网页翻译订阅不等于API权限。
2. 选择 DeepL API，并选择对应 Free/Pro 方案。插件固定连接 api-free.deepl.com 或 api.deepl.com。
3. 在“DeepL API Key”选择器中创建密钥，例如名称 research-radar-deepl，将真实Key输入 Obsidian 的密钥管理窗口。插件配置只保存这个名称。**不要把Key放进地址、模型名、主题JSON或聊天。**
4. 授权在线发送并保存，点击连接诊断读取已用字符/额度；它不发送论文。再点击试译，成功后使用批量翻译。
5. HTTP403通常是权限、密钥或方案不对应；429限流；456额度用尽。核对服务方控制台后手动继续，插件不会自动重试收费请求。

### OpenAI、Gemini、Claude、通义千问、智谱 GLM

这些是独立的官方AI API适配器。需要各平台自己的开发者API密钥；ChatGPT、Gemini或Claude网页订阅不能代替API权限。试译、模型生成和部分诊断可能受账户限额约束；本插件没有费用硬上限。先查本人控制台，不默认任何AI服务永久免费。

| 服务 | 本插件连接方式 | 模型设置 |
|---|---|---|
| OpenAI | api.openai.com，Responses原生结构化输出 | 预填gpt-6-luna；以账户支持的模型为准 |
| Google Gemini | generativelanguage.googleapis.com，generateContent | 预填gemini-4-argon；需支持文本生成 |
| Anthropic Claude | api.anthropic.com，Messages原生接口 | 预填claude-haiku-5-5；需有相应API权限 |
| 通义千问/百炼 | DashScope，Chat Completions兼容 | 预填qwen-plus；可选北京/国际新加坡，密钥须对应区域 |
| 智谱 GLM | open.bigmodel.cn，Chat Completions兼容 | 默认留空，填本人可用模型，或清空后检查模型清单 |

1. 选择服务，填模型。各服务独立保存模型名和密钥引用；切换后不会借用其他服务密钥。
2. 在对应API Key选择器中创建/选择密钥。不要把明文Key交给Agent、粘到主题JSON、基础地址或模型框中。
3. 开启“允许在线发送所选标题与摘要”和“启用手动翻译”，点击保存。
4. “检查连接与模型”读取元数据，不生成论文译文。模型框为空时尝试列表；可点击返回模型填入草稿后保存。列表可能分页或包含不能翻译的模型，未完整分页；模型存在也不代表JSON输出/计费可用。
5. “试译一句”才实际生成译文，可能收费；确认限定关系、47/50等数值后，再选1–3篇论文翻译。
6. 模型未完成输出、触发安全拒绝、非JSON、空摘要译文或限流都会暂停，不保存半篇为成功，不自动换更贵模型。

预填名称是2026-11-04的官方文档示例，不保证每个账号可用或是最便宜方案。智谱模型清单接口未必可用，可按官方控制台填名称并手动试译。百炼专属业务空间地址可选下方“自定义兼容API”；不要把专属密钥发给不相干地区或代理域名。

参考：[OpenAI结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)、[Gemini生成接口](https://ai.google.dev/api/generate-content)、[Claude消息接口](https://platform.claude.com/docs/en/api/messages/create)、[百炼兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[智谱兼容接口](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)。

### DeepSeek 与自定义兼容服务

DeepSeek：选择对应服务，密钥通过选择器建立独立引用；模型预填 deepseek-flash（2026-11-04官方文档示例），账户支持与命名变化以服务方为准。官方基础地址固定 https://api.deepseek.com。

自定义：填写供应商的HTTPS基础地址，如 https://your-provider.example/v1（示例域名不可直接使用）；程序追加 /chat/completions，不要填写完整请求路径。填写真实可用模型名，并为此服务单独选择API密钥。更改供应商地址时重新核对密钥归属，避免把其他供应商的密钥发送过去。模型必须支持 response_format=json_object、非流式返回和完成状态 stop；仅支持Responses或其他协议的API不适用。

连接诊断会读取 /models，不发送论文；部分供应商没有模型清单接口，会检查失败但实际翻译接口仍可能可用。核对文档后可以直接使用“试译一句”。试译和每次生成可能收费，额度由供应商管理，插件不设置硬性费用上限。服务报错/截断/JSON不完整会暂停批次，保留原文，不自动换到本地或其他云端。

### 选择建议与排障

少量免密钥试读可先用Google或MyMemory；有大量摘要时优先评估官方微软/DeepL的账户额度，或轻量AI API。Bing作为实验性候选，先过连接检查。未公开研究内容使用本地模型。选择在线服务不会启动Ollama，但需要网络；本次没有足够账号验证比较各云服务精度、速度和费用，不做排名承诺。

401/403先核对密钥、区域及API权限；429/456核对额度或限流后手动继续。切服务保存后再翻译，失败任务保留进度；不会自动合并不同服务输出。连接检查成功但试译失败，需核对模型是否支持该协议和JSON输出。不要反复点击收费请求。

### 密钥管理、缓存和退出

密钥选择需要当前 Obsidian 提供 SecretStorage/SecretComponent。缺少时界面提示升级，仍可用本地或免密钥服务；不会退回到data.json明文保存。不要把整个密钥存储或私人配置随安装目录分享。

新缓存按服务、模型、目标语言及自定义地址隔离；Bing和百炼还区分服务区域；DeepL还按Free/Pro分开。旧本地译文仍可预览（注明原模型），需要所选服务的新译文时手动批量翻译。不同在线服务的译文不会相互冒充；切回原服务可读回其缓存。空摘要只翻译标题，绝不生成摘要。关闭/重启插件会暂停批次，不自动续跑。暂停通常等待当前请求，付费API超时将关闭连接；免密钥请求超时后底层请求可能仍在结束，但不能撤回对方已接收的数据或保证不计费。
